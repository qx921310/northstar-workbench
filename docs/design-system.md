# 北极星设计语言 v0.2（提案）

状态：待确认；本文是后续设计和实现的依据，不代表现有界面已全部符合。

[查看整体概念图](design/northstar-unified-concept-v1.png)。概念图用于评审视觉风格，不是交互或功能规格：图中的邮件分类、写邮件按钮、数字、删除文案及示意数据不作为新增功能或实际数据；以本文和已确认的产品需求为准。

## 基调

**安静的空间桌面**：以浅色、蓝色线性图形和柔和圆角作为品牌与界面的共同语言。保留适度层次和悬浮反馈，降低渐变、透明与阴影的存在感。信息结构以目前的收件箱为基准：首页更有空间感，功能页更克制、更紧凑。参考 iOS 的清晰层级和操作反馈，建立北极星自己的组件体系，不照搬具体产品界面。

适用范围包括首页、待办、热点、Agent、笔记、收件箱、服务、设置、弹窗和后续新增页面；日间与夜间同时设计、同时验收。业务功能和数据来源不因统一外观而改变。

## 品牌与图标家族

- 品牌以四角北极星为核心，采用**浅蓝圆角容器、蓝色星形**；功能图标采用同一容器、蓝色线条、视觉粗细和留白。品牌图形可稍饱满，但不得另用深蓝实心底、强高光或厚重立体材质。
- 应用图标、窗口图标、任务栏及桌面快捷方式应从同一源图形导出；按小尺寸专门检查细节及对比度，禁止直接把大图缩小后不检查。不得因为导出限制改成另一套视觉风格。
- 默认图标、按钮图标、首页入口及底部导航共用同一绘制规范：建议以 24 × 24 画布、2 px 线宽、圆角端点为起点，保持视觉大小一致；容器与无容器用法均需遵循同一笔触。图形与容器的最终尺寸经真实截图校验。
- 日间默认图标为浅蓝底、蓝色图形；选中使用更明显的浅蓝底和深蓝图形，悬停、聚焦分别增加轻微表面变化与清晰焦点环；禁用以降低对比但保留可辨识度。夜间使用深蓝灰底、柔和浅蓝图形，背景、前景和边界按主题语义变量定义。
- 品牌标识不替代业务图标，普通位置不重复叠加星形作为装饰；品牌色、图标与文字应在浅色及深色背景下同样清楚。GitHub 等第三方标识保留可识别性，同时控制容器和视觉占比，不能随意改变官方商标形状。
- Logo 和功能图标允许用途上的微小差异，但在形状、轮廓、笔触、底色、前景色、圆角、材质、留白、状态和尺寸上必须可追溯至同一套规则；不得以“品牌图标不同”作为跳过统一评审的理由。

## 页面框架

- 应用背景贯穿窗口，业务模块不再套一层巨大的外框；顶角系统操作、底部悬浮导航固定于窗口，不随正文滚动。
- **一体化窗口（代码已接入，待实机验证）**：取消当前独立的系统标题栏外观，让工作台背景延伸到窗口顶部；不单独重复展示应用图标和名称。将最小化、最大化/还原、关闭保留在右上角，与提醒、主题和版本信息错开，使用相同的图标笔触、色彩和交互状态；关闭操作的悬停状态应清楚可辨。
- 顶部保留明确的可拖动空白区域，交互按钮、输入框、页签和提醒弹层不能触发窗口拖动。双击拖动区切换最大化/还原；窗口边缘与四角支持拖拽缩放，最大化时内容不被屏幕边缘或任务栏裁切。键盘访问和 Alt+F4 等系统操作须保持可用。
- Windows 窗口贴靠、最大化按钮悬停布局、DPI 缩放、多屏与多分辨率行为必须在 Windows 实机验证；如果自绘窗口不能可靠保留某项系统行为，需要优先考虑可保留原生能力的实现，并在交付时明确差异。页面吸顶栏、模态窗口和顶部操作不得互相遮挡。
- 功能页采用同一内容宽度、左右边距和标题基线。页首展示模块名称和该页面必需的主要操作，正文区域独立滚动；内容少时保持视觉平衡，内容多时从顶部自然排列，不强制所有页面居中。
- 有筛选、页签或搜索的页面，向下滚动时将页首收缩成紧凑吸顶栏；常用操作仍可见，正文在其下独立滚动。返回顶部时恢复原尺寸。待办等无筛选页只保留紧凑标题，不制造无用页签。
- 列表和正文容器在滚动视口内始终维持圆角裁切；顶部、底部不能出现被截断的尖角，正文不能穿过吸顶栏。小窗口先压缩间距和控件，再在必要的区域滚动，不能遮挡按钮。
- 底部导航默认收起为紧凑入口，悬停或键盘聚焦时展开，浮在正文上方，不挤压内容；给正文末尾留足可访问的滚动空间。图标与文字对齐，不得贴边；触屏或无悬停设备保持可操作的可见入口。
- 首页保留四张等尺寸、适度交叠的空间卡片：今日热点、我的待办、收件箱、我的服务。悬浮或聚焦时被选卡升至顶层并适度放大，不能遮挡不可恢复的重要操作；窄窗口改为网格。

## 基础变量

下列数值为统一实现时的初始设计值，需要在实际页面和 Windows 深浅主题中验证对比度与视觉效果；不要求通过覆盖现有样式立即套用。

| 类型 | 规则 |
| --- | --- |
| 字体 | Windows 优先 `Segoe UI Variable` / `Microsoft YaHei UI`，其他平台使用系统无衬线字体；中文、英文、数字采用一致字重层级。 |
| 字号 | 页面标题 32 px，分组标题 18 px，正文 14–16 px，辅助信息 12–13 px；需要时响应窗口缩放，不依赖超大标题撑版。 |
| 间距 | 使用 4 / 8 / 12 / 16 / 24 / 32 px 阶梯；页面边距 24–40 px，卡片内边距通常 20–24 px，控件间距通常 8–12 px。 |
| 圆角 | 容器 20 px；弹窗 20 px；输入框与按钮 12 px；小标签 8 px；头像与角标为圆形。列表行依靠容器裁切，不单独出现尖角。 |
| 操作尺寸 | 按钮和输入框常规高度 40–44 px；图标按钮至少 36 × 36 px，触屏目标至少 44 × 44 px。文字不可因空间不足而裁断。 |
| 阴影 | 静态卡片用轻阴影；悬浮卡片和弹窗才提高阴影与层级，避免每个元素都漂浮。 |

### 语义颜色（初始值）

| 语义 | 日间 | 夜间 | 用途 |
| --- | --- | --- | --- |
| 画布 | `#E9F0FA` | `#172130` | 背景基色；渐变作为装饰，不能承载文字对比 |
| 主表面 | `#F8FAFD` | `#273548` | 内容卡片、列表和弹窗 |
| 次表面 | `#E7EFFB` | `#34465D` | 页签底板、次要操作、吸顶栏 |
| 主文字 | `#202A38` | `#E7EDF5` | 标题、正文 |
| 次文字 | `#52627A` | `#C0CCDC` | 日期、说明、辅助状态 |
| 强调 | `#126BE8` | `#A6CDFF` | 链接、选择状态；深色下按钮底色单独校验 |
| 成功 | `#16845E` | `#8AD6B3` | 成功、已连接、提醒已触发 |
| 警告 | `#996000` | `#F4CA81` | 需关注、等待 |
| 危险 | `#BD3444` | `#FFB1B5` | 删除、失败 |
| 分割线 | `#D6E0ED` | `#52647A` | 边框、行分隔 |

颜色必须按语义变量引用，不在业务组件里随意新增蓝、灰或暗色。正文及必要状态文字目标对比度至少 4.5:1，大号文字至少 3:1；边框、图标和焦点环也需可辨识。禁用状态不能仅靠降低整体透明度导致内容消失。概念图中的色块仅示意，实施前以各状态实际背景逐一测量；常态浅蓝图标底和选中底分别定义变量，不从截图取色作为最终值。

## 组件与交互

| 组件 | 统一规则 |
| --- | --- |
| 主按钮 | 每个局部操作区域原则上只有一个蓝色主按钮；次要按钮用浅色表面，危险操作用红色并配文字。 |
| 选择与输入 | 单一高度、边框、圆角和焦点环；显示标签、占位、错误及禁用状态。错误紧邻字段，不能只让按钮失效。 |
| 页签 | 收件箱的横向卡片式导航作为模板；选中、悬停、聚焦、禁用状态统一。可拖拽项要有明确抓手、移动反馈和键盘替代操作。 |
| 列表 | 标题、辅助信息、时间和操作保持固定对齐规则；支持长文本自然换行。加载、空结果、失败与重试均有明确状态。 |
| 弹窗 | 同一遮罩、宽度阶梯、标题、关闭入口和底部操作布局；打开时焦点进入，支持 Esc 和键盘操作，关闭后焦点返回触发控件。删除待办沿用已确定的「确认删除」及红色删除、绿色取消。 |
| 日期时间 | 新建与编辑使用同一控件：单击弹出选择，双击进入输入；确认、取消、错误和过去时间限制一致，弹层不被裁切。 |
| 提醒与角标 | 未读邮件用数字气泡，零不显示；Agent 数量不显示气泡。待办提醒的铃铛显示待触发或已提醒状态，悬浮及键盘聚焦显示日期。 |
| 加载与反馈 | 优先呈现已有缓存并在后台更新；手动刷新有进行中、成功或失败反馈，禁止看似可点击却无反馈。 |
| 图标 | 统一使用同一套线性图标，常规 18–20 px、相同线宽；状态须搭配文字、形状或无障碍名称，不能只依赖颜色。 |

交互时长以 150–220 ms 为主，首页卡片可使用约 240–300 ms 的柔和缓动；页面切换、吸顶收缩和悬浮反馈不阻塞点击。支持系统“减少动态效果”：取消放大、位移和持续旋转，同时保留状态提示。

## 各模块落地

1. **收件箱**：作为功能页模板，统一页签、筛选栏、列表和详情；切换和滚动时导航、圆角和刷新状态保持一致。
2. **待办**：保留进行中、已完成、新增的业务分区；新建和编辑共用表单、日期、状态、确认弹窗。
3. **笔记**：工作台笔记与 Obsidian 共用页首、搜索和列表组件；目录与同步等差异通过操作项表达。
4. **热点**：采用相同标题、列表、按钮和分页组件；长名称与简介允许换行。
5. **服务**：采用同一吸顶栏与滚动区域，服务状态用统一状态标签，缓存时间和刷新结果可见。
6. **Agent**：以后单独优化接入能力，本规范只约束其未来页面框架和基础组件，不改变现有运行机制。
7. **首页**：保留空间卡片，但使用相同的文字、颜色、图标及深色主题变量。

## 开发和验收约束

- 新页面优先组合现有页面框架、按钮、输入框、列表、弹窗和状态组件；确需新变体时先补充规范，并说明适用场景。
- 建立品牌与组件清单，逐项覆盖桌面/任务栏/窗口图标、首页卡片、所有底部导航、模块页签、列表操作、空状态、弹窗、日期选择、提醒和更新状态；同屏审查应用 Logo 与功能图标，不能只单独审查某个模块。
- 首先制作真实可交互的组件样板，覆盖浅色/深色、默认/悬停/聚焦/选中/禁用/加载/错误及长文本，再以同一组件实现首页和各模块；概念图的绘制不能替代真实窗口检查。
- 将语义色、字号、间距、圆角、层级和动效收敛为设计变量；逐步移除同一选择器的重复覆盖，不继续通过追加临时样式修复局部。
- 一次组件改动需检查全部使用场景和日夜主题；至少覆盖正常、悬停、聚焦、禁用、加载、错误、空状态及长文本。
- 至少在 1350 × 900、较小窗口和高 DPI 缩放下检查；滚动到顶部、中段、底部，确认吸顶栏、圆角、悬浮导航和操作不被裁切或遮挡。
- 使用真实界面截图或可交互样板评审视觉一致性，并结合键盘、减少动态效果和自动化回归；视觉检查通过后再批量替换，不以一次局部截图代表全部完成。
- 先确定基调，再建立变量与通用组件，最后按模块迁移；每一阶段单独验证，不重写或改动无关业务逻辑。版本和发布仍遵循项目已有规则。
